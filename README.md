# GitManager

使用 WPF 与 .NET 10 编写的 Windows Git 管理器，直接调用本机 Git，可离线查看改动、提交版本和恢复代码。

## 使用

通过左侧“服务云”登录服务云账号，可读取“文档 → Git”中的实际仓库，克隆到本机，或将当前本地仓库连接后同步。也可输入名称“新建并同步”。密码保存在 Windows 凭据管理器中，配置文件仅保存服务地址、账号和代理地址。当前内网连接使用 WindowsStream 的 `http://127.0.0.1:1080` 代理，可在窗口中修改，留空则直接连接。已有其他远程时使用独立的 `servicecloud` 远程。同步继续遵循服务云仓库权限和分支保护规则。

1. 启动 `GitManager.exe`，自动识别桌面、文档、已添加仓库同级目录及程序所在项目中的本地仓库并加入列表，刷新时也会补充新仓库；返回窗口时也会自动检查，两次检查至少间隔一分钟。可通过“添加仓库”手动添加、新建或克隆仓库。左侧列表按仓库的远程 Git 服务分组（服务云、GitHub、其他主机、本地路径、仅本地），各组之间以细线分隔，组内保持原有顺序。点击仓库后先显示最左侧的“说明”页，列出位置、分支、全部远程地址（各远程之间以细线分隔）和 README。
2. 在“改动”中查看并排差异，点击“提交到本地”会自动全选当前全部改动，按真实改动生成中文说明并保存到本地。Ctrl+Enter 使用相同流程；提交时会生成或复用对应改动的说明，不会自动推送。
   也可点击“自动总结”，通过已配置的集团 AI、Claude 或千问按勾选文件的真实差异生成中文提交说明，未勾选文件时会自动勾选全部改动，生成后可编辑。生成期间可取消；手动编辑草稿或统计范围发生变化时，不会覆盖当前草稿。总结只填入说明，不会自动暂存、提交或推送。
3. 在“本地”和“GitHub / 远程”中分别查看提交与文件，或恢复指定版本。每侧最多加载当前分支最近 300 条提交。历史浏览独立加载，支持连续切换；已读取的文件列表和差异会缓存，并预读相邻提交。
4. 恢复前，相关未提交修改会保存为 Git stash，可通过“恢复点”取回。恢复不重写历史；检查恢复后的改动，再提交为新版本。
5. 通过“远程”设置 origin 地址，在顶部选择远程分支。版本栏显示两端的提交号、待推送和待拉取数量；启动后在后台预读列表中的仓库，切换时立即显示已有页面，再后台校验本地状态、获取远程记录。各仓库分别保留提交草稿、勾选和各页中的选择；首次尚未预读的仓库显示后继续加载，期间仍可切换其他仓库。也可点击“获取”手动更新。
6. 点击“对比”查看当前本地与远程版本的差异；也可在“对比”页任选两个历史版本，逐文件查看并排差异。
7. 点击“同步”前会重新获取远程状态。本地领先则推送，远程领先则快进更新本地；双方各有新提交时，先点击“合并远程”。推送不使用强制覆盖，并遵循实际选择的远程分支。

8. “说明”页的“自动上传”默认勾选，程序每 30 秒检查该仓库：改动文件停止修改 1 分钟后，按“提交到本地”相同的流程全选改动、生成说明并提交，再获取远程状态并推送；之前未推送成功的提交也会补推。可对每个仓库单独开关，手动关闭后会记住选择，窗口隐藏到托盘时仍继续执行。推送不使用强制覆盖；远程有本地尚未包含的提交、存在冲突或正在合并时只提交到本地或暂停，在“说明”页显示原因，十分钟后重试，需手动“合并远程”后才能继续推送。未设置远程时只保存到本地。在 `settings.json` 的 `AutoUpload` 中可调整 `QuietSeconds`（等待时长）、`CheckIntervalSeconds`（检查间隔）和 `RetryMinutes`（失败重试间隔）。提交范围以 `.gitignore` 为准，请确认不需要上传的文件已被忽略。

有冲突时，“改动”页可逐个文件选择“采用本地”“采用远程”，也可编辑文件并标记为已解决。处理完全部冲突后点击“完成合并”，再推送版本；“取消合并”返回合并前状态。

同名仓库对比窗口会调用现有配置的大模型分析目录关系、双方额外提交、未提交改动、忽略项和清理建议。分析支持取消和重新生成；依据来自现场 Git 读取，浅克隆、缺少对方提交对象或读取失败会明确标记无法确认。模型调用结束后会复查，仓库变化则丢弃旧建议。分析不会提交或删除文件；删除仍需点击对应卡片并确认。模型顺位及内网仓库限制与大模型总结设置一致。

远程列表来自本地保存的远程跟踪记录。界面显示最近获取时间；网络或认证失败时明确标记为缓存，不把旧记录当作刚获取的 GitHub 状态。同步仅处理已提交版本，不会自动提交工作区修改。

切换分支、拉取和取回恢复点前，需先处理当前修改。仓库中存在合并或变基等未完成操作时，应先完成该操作。恢复点不会自动删除；有冲突时请保留记录并解决冲突。

## 配置

安装 Git for Windows，默认程序路径为 `C:\Program Files\Git\cmd\git.exe`，也可在“设置”中修改。远程认证使用 Git 自身的凭据管理器；不要把令牌或密码填入仓库地址。

用户配置与日志保存在当前用户的 `AppData\Local\GitManager` 下，分别为 `settings.json` 和 `logs`。不需要配置环境变量。设置中填写的提交姓名和邮箱仅写入当前仓库，不修改全局身份。提交邮箱默认留空，可在仓库设置中单独填写；普通提交和合并提交均使用此规则。

在“设置 → 大模型总结 → 集团 AI”中点击“登录”，在内置窗口完成一次集团 AI 登录，支持企业微信扫码。程序验证登录后保存会话到 Windows 凭据管理器，自动续期，不保存密码；需要重新登录时会打开同一登录窗口。启用后，服务云和内网仓库使用集团接口总结，失败时停止，不转给 Claude 或千问；外网仓库始终按 Claude 优先、千问兜底的顺位处理。`LuxAi` 配置节保存接口、HTTP 内网代理、超时和输入长度；默认代理为 `http://127.0.0.1:1080`，不读取环境代理或回退直连。每次总结新建独立会话，避免不同仓库共用上下文。当前平台未公开基础模型型号、完整用量和费用，显示待确认。

公网仓库使用原有 Claude、千问顺位，与是否启用集团 AI 无关。在“设置 → 大模型总结”中填写千问 API Key，默认使用百炼北京接口的 `qwen3.8-flash`，关闭思考，最多输出 512 Token；密钥仅保存到 Windows 凭据管理器，配置文件的 `Qwen` 节保存接口、模型、长度限制及超时。也可填写百炼业务空间专属接口地址。取消“启用大模型总结”可切回本地规则。

未启用集团 AI 时，服务云和内网 Git 仓库使用本地规则，不调用公网大模型，也不复用其总结缓存。按全部远程的实际拉取、推送地址判断，包括 Git 地址重写；`servicecloud` 远程、配置的服务云域名、内网 IP、解析到内网的主机及本地路径均适用。无法确认远程地址时也使用本地规则。启用集团 AI 后，这些仓库可使用集团内接口。此规则同时适用于“自动总结”“提交到本地”和同名仓库分析；同时分析多份仓库时，只要包含内网仓库就走集团 AI。

`Qwen.PublicGitHosts` 列出明确的公网托管域名，默认包含 GitHub、GitLab、Gitee 和 Bitbucket，用于避免代理虚拟 DNS 地址造成误判；服务云域名和内网 IP 的判断优先于此列表。

千问总结会发送当前所选文件的真实 Git 差异和未跟踪文本内容；二进制内容省略，长内容按配置截断并明确标记。固定规则放在请求前缀，动态差异置于末尾，以便利用云端隐式缓存，但不保证命中。实际输入、缓存命中、输出 Token 和耗时写入中文日志，未返回的数据明确标记为“未返回”；不记录密钥、请求正文或源码。

相同仓库、模型、提示词和实际内容的总结会复用本地结果，缓存最多保留 100 项；内容指纹涵盖完整文件字节，即使修改前后行数相同也不会误用。生成结束后会再次检查内容，变化时停止提交。接口失败、未配置密钥或回复截断时明确报错并停止，不自动改用本地规则提交。

每次调用后，状态栏右侧显示按接口实际 Token 用量计算的人民币预估费用，日志同时记录用量、缓存比例、金额及计价日期。普通输入与缓存输入分别计价；缓存用量缺失时显示费用范围，总用量缺失或模型、地域与价格配置不匹配时显示“费用待确认”。本地缓存及内网仓库的本地规则显示本次 ¥0。单价在 `Qwen.Pricing` 配置，默认采用 2026-10-21 千问3.8 Flash 北京地域官方标价（每百万 Token：普通输入 ¥0.8、缓存输入 ¥0.1、输出 ¥2.7）。预估不包含赠送额度及活动优惠，实际以百炼账单为准。

在“设置 → 千问总结 → 用量统计”中查看全部或今天的实际调用次数、输入、输出、缓存 Token、预估费用及逐次明细，底部显示当前配置单价。Claude 调用同样记录，“来源”一列标明每次是 Claude 还是千问总结，调用次数下方分别显示两者次数；Claude 使用本机登录账号额度，不计入千问费用和缓存统计。记录保存在用户数据目录的 `qwen-usage` 中，包含调用结果、用量、金额和计价配置，不保存密钥或源码。旧日志可确认的记录会自动导入并去重；缺失的历史用量或费用保留待确认，本地规则和本地结果缓存不计入 API 调用次数。

自动发现可在 `settings.json` 的 `RepositoryDiscovery` 中配置：`Enabled` 开关、`Roots` 额外扫描目录、`MaxDepth` 扫描深度（默认 6）、`MaxDirectories` 目录数上限（默认 20000）。每轮最多扫描 15 秒，跳过目录链接、网络路径和常见构建依赖目录，通过 Git 验证 `.git` 目录及工作树的 `.git` 文件。自动加入的仓库默认开启“自动上传”；手动关闭后不会自动提交或推送。手动移除的仓库记录在 `IgnoredRepositories` 中，扫描时不会重新加入；手动添加该仓库会解除排除。

快捷键：`F5` 刷新、`Ctrl+O` 添加仓库、`Ctrl+Enter` 提交。

点击窗口关闭按钮会隐藏到右下角托盘，Git 操作继续执行。双击托盘图标或右键选择“显示主窗口”恢复；右键选择“退出”才会结束程序，执行 Git 操作时需等待完成后再退出。

左下角可一键切换黑夜与白天模式，选择会自动保存。也可在“设置 → 主题”中选择跟随系统；窗口标题栏和应用弹窗同步切换。

## 构建

安装 .NET 10 SDK，在 Windows 上执行：

```powershell
dotnet build .\GitManager.csproj -c Release
dotnet publish .\GitManager.csproj -c Release -r win-x64 --self-contained true -o .\publish\win-x64
```

发布目录中的 `GitManager.exe` 可直接启动，Git 仍需在本机安装。文本差异预览支持不超过 2 MiB 的 UTF-8 文件，最多显示 10000 行；二进制文件只显示状态。

## 目录

- `Models/`：仓库、提交、文件与差异数据。
- `Services/`：Git 进程调用、仓库读写、恢复、配置与日志；`Versions/` 包含版本读取、对比、同步与冲突处理。
- `ViewModels/`：仓库、改动与历史状态；`Versions/` 管理远程记录和版本对比状态。
- `Views/`：差异查看器和通用对话框；`Versions/` 包含版本栏、远程历史、对比与冲突处理界面。
- `Themes/`：沿用 AutoCopy 的配色和通用控件样式。
- `Checks/`：使用真实临时仓库验证本地 Git 流程。
